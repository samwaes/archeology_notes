# Product objectives

## Primary question

Can archaeologists and conservation professionals keep spatial models, field observations, photographs, documents and interpretation together without creating more administrative work?

## First useful product loop

```text
project / site
      ↓
3D spatial workspace
      ↕
physical objects / areas
      ↕
notes · photos · voice · documents · observations
      ↓
catalog + search + provenance
      ↓
team review
```

## Product principles

1. Physical object is not the same thing as a scan or model.
2. Original source assets remain immutable.
3. Derived assets keep explicit provenance to their source.
4. Spatial observations belong to physical context and survive representation changes.
5. Field capture should take seconds.
6. Authorship and acquisition dates are never lost.
7. Private, Project and Public visibility are explicit states.
8. AI output is always distinguishable from human observations and source evidence.
9. Registration uncertainty must be visible when comparing geometry over time.
10. Open formats and heritage standards should keep future institutional integration possible.

## First external pilot objective

A Hupla-authorised archaeologist should be able to open Casignana, navigate the photographic 3D model, attach a photo/voice/text observation to a real location, find that record in the catalog, and later return from the catalog to the same spatial context.

A second project member should see project-shared records while private records remain invisible.

## Non-objectives for the first pilot

The first pilot is not intended to replace:

- Arches
- institutional collection-management systems
- a full GIS
- a digital asset management platform
- specialist photogrammetry processing software
- point-cloud registration software
- conservation-science laboratory systems

The prototype should connect evidence and workflow first, then prove which deeper integrations are valuable.
